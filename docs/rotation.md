# 侧放页回正

有些包里的跨页是**横躺着存成竖版**的：例如一张 1138x2160 的图其实是横版跨页逆时针转了 90° 存放，顺时针转 90° 才能正常阅读。一本里可能有多页这样。

## 判定依据

Kmoe 系包会为**每一张**侧放的页遗留一张原始跨页图 `<图名>-RAWIMAGE.<ext>`。把候选页的四个朝向分别与它做归一化相关度，取「宽高比一致且最像」的朝向 —— 方向是判出来的，不靠猜。

- 实测：`[Kmoe][少年犯之七人]卷01` 顺时针 90° 相关度 0.87、卷 02 1.00；方向不对的朝向只有 0.1 上下
- 参照图扩展名可与页图不同：`[Kmoe][電鋸人2]話001-005[話098-102]` 是页图 `.jpg` + 参照图 `.png`，该包有 11 页被回正

## 候选范围

- `cover.html` 引用的封面图
- 正文第 1 页的图
- **任何带同名参照图的页**（等于包自己声明了「这页是侧放的」）

判为已正立的页一个像素都不动；没有参照图的页一律不碰。

## 明确不做的事

- **没有参照图、相似度不足、参照图读不出 → 一律不旋转。** 曾经有过一条「尺寸兜底」规则（页宽 < 全卷页宽中位数 × 0.85 且宽高比 < 0.6 就按顺时针 90° 转），它判不出顺/逆、属于猜方向，会把本来正常的窄页转坏（`[Kmoe][女僕咖啡廳]卷01` 全包没有参照图，正是被它误转过），已删除
- `--rotate-cover=90/180/270` 只**覆盖自动判出的方向**，不改变「是否侧放」的判断，对所有判出侧放的页生效
- `--no-rotate-cover` / `--rotate-cover=off` 完全关闭：图片一个字节都不动（站点卡片页的移位与图片处理无关，照常执行）

## 日志

不逐页写日志：判为已正立、没有参照图、相似度不足都静默略过。确有页被回正时，在「页序已按页码重排完成」之后汇总一行「已回正 N 张侧放页」（N = 实际旋转的图片数，同一张图被多页引用只算一张）。只有图读不出、无法解码、重新编码失败这类异常才逐条提示。

## 画质

JPEG 旋转后必须重编码（质量 95，一次代际损失，肉眼不可见），PNG 无损。

## 图形界面侧

界面上没有回正开关（默认就是按参照图回正）。需要关闭或指定方向时，改 exe 同目录 `KmoeFix.json` 的 `rotate_cover` 字段：`"off"` 关闭，`"90"` / `"180"` / `"270"` 指定方向，留空即默认。
